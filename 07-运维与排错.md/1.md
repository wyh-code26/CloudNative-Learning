## 一、跨系统文件拷贝：Windows ↔ Ubuntu 换行符冲突

**现象**：在 Ubuntu 上写的 Shell 脚本、Markdown 文件，复制到 Windows 后用记事本打开，所有内容挤成一行；反向操作时同理。

**根因**：
- Linux 用 `LF`（`\n`，ASCII 10）作为换行符
- Windows 用 `CRLF`（`\r\n`，ASCII 13 + ASCII 10）
- Windows 记事本只认 `CRLF`，看到单独的 `LF` 不换行
- Git 在执行 `git add` 时也会警告 `LF will be replaced by CRLF`

**解决**：
- 在 VS Code 右下角点击“LF”或“CRLF”，手动切换换行符格式
- Git 全局配置：`git config --global core.autocrlf true`（Windows）或 `input`（Linux）
- 写跨平台脚本时，始终用 VS Code 而非记事本

**教训**：跨系统文件交换时，换行符是第一道隐形门槛。

## 二、`reboot -f` 导致系统崩溃

**现象**：分区操作后执行 `sudo reboot -f`，系统重启后无法进入桌面，dmesg 报 `Input/output error`，随后陷入 `grub>` 救援模式。

**根因**：
- `reboot -f` 调用的是 `reboot()` 系统调用，**直接跳过 systemd 的正常关机流程**
- 正常关机会：① 停止所有服务 → ② 卸载文件系统 → ③ 同步磁盘缓存 → ④ 向内核发送重启信号
- `-f` 跳过全部步骤，导致文件系统元数据（超级块、inode表）在写入中途被暴力中断

**修复过程**：
1. 制作 Ubuntu Live USB 启动盘
2. 进入“试用 Ubuntu”（Try Ubuntu）
3. 尝试 `sudo fsck -y /dev/nvme0n1p2` —— 失败，提示超级块损坏
4. 尝试恢复备份超级块 —— 失败，所有备份均已损坏
5. 尝试通过 GRUB 命令行手动启动 —— 失败，内核模块（LVM）缺失
6. **最终方案：重装系统**

**教训**：
- **永远不到万不得已不要用 `-f` 参数**
- 正常重启用 `sudo reboot`，卡死时优先尝试 `Alt + SysRq + REISUB`（安全重启组合键）
- 强制关机（长按电源键）只在所有其他方式都无效时使用
- 不要在分区刚调整完就强制关机——此时文件系统处于脆弱状态

## 三、Ventoy 制作多系统启动盘失败

**现象**：用 Ventoy 制作 Windows 11 + Ubuntu 26.04 双系统启动盘，Ubuntu ISO 能正常启动，Windows 11 ISO 启动时报错。

**尝试的方案及结果**：
| 方案 | 结果 |
|------|------|
| Ventoy 1.0.79 稳定版 | Windows ISO 启动失败 |
| Rufus（在室友的 Windows 电脑上） | 成功，但只能做单系统启动盘，来回切换太麻烦 |
| 手动分割 Windows ISO | 失败，install.wim 超过 4G 无法存入 FAT32 |
| Ventoy 最新版 | 成功！新版修复了与 Win11 镜像的兼容性问题 |

**教训**：
- **制作启动盘时，Ventoy 必须用最新版本**
- 对于超过 4GB 的单个文件（如 Windows 的 `install.wim`），Ventoy 在 NTFS 分区下直接存放 ISO，比 Rufus 的自动分割方案更稳定
- 多系统启动盘优先用 Ventoy，单系统启动盘优先用 Rufus

## 四、Windows 11 安装卡在 OOBE 强制联网环节

**现象**：用 Ventoy 启动 Windows 11 安装程序，安装进入 OOBE（Out-Of-Box Experience）阶段，出现“让我们为你连接到网络”页面，要求必须联网，但不提供跳过选项，且 Shift + F10 和 `oobe\bypassnro` 均失效。

**这是为什么**：Windows 11 家庭版（Home Edition）已从底层剥离离线账户功能，强制要求登录微软账户才能完成安装，不像 Win10 和 Win11专业版可以创建本地用户。

**尝试的解决方案及结果**：
| 方法 | 结果 |
|------|------|
| Shift + F10 调出命令行 → `oobe\bypassnro` | 失效（家庭版封堵了此方法） |
| 拔掉网线 | 无效（系统强制要求连接 Wi-Fi） |
| 反复重试 | 无效 |
| **从另一台电脑下载无线网卡驱动 → 用 U 盘拷到这台电脑 → 加载驱动 → 连接 WiFi → 完成安装** | **成功！** |

**教训**：
- **Windows 11 家庭版 OOBE 联网是设计，不是 Bug**——不要试图跳过，接受这个事实
- **提前下载无线网卡驱动**：在装系统之前，用另一台电脑下载你网卡的 Windows 驱动，存到 U 盘里。OOBE 阶段如果需要联网，加载驱动即可
- 如果不想被强制联网，可以选择 Windows 11 专业版（可创建本地用户）

## 五、GRUB 引导损坏 + LVM 模块缺失

**现象**：`reboot -f` 后系统重启，直接进入 `grub>` 救援模式，无法显示启动菜单。

**尝试的修复方法及结果**：
| 方法 | 结果 |
|------|------|
| `set root=(hd0,gpt2)` + `linux /vmlinuz` + `initrd /initrd.img` + `boot` | 失败，提示文件未找到 |
| 完整路径启动 `/boot/vmlinuz-...` | 失败，提示分区外读写错误 |
| 加载 LVM 模块 `insmod lvm` | 失败，当前 GRUB 版本缺失 `lvm` 命令工具 |
| Live USB + `boot-repair`（推荐修复） | 失败，分区已损坏至无法挂载 |

**最终方案**：重装系统 + 提前备份所有数据至外部 U 盘。

**教训**：
- GRUB 救援模式能修复的问题有限——文件系统本身坏了，引导程序无法起作用
- Ubuntu 默认安装可能启用 LVM（逻辑卷管理器），在救援模式下需要额外的 LVM 模块支持
- **最好的救急方式是有完整的备份 U 盘 + Live USB 启动盘**

## 六、快瞳科技 API 接口返回 APIG.0303 错误

**现象**：调用快瞳科技身份证二要素核验 API，始终返回以下错误：

```json
{"error_msg":"Incorrect app authentication information: Authorization header is missing","error_code":"APIG.0303"}
```

根因：APIG.0303 是华为云 API 网关的官方错误码，意指“应用认证信息错误”。本 AppCode 是以“简易认证”方式使用的，但商家侧未为该 API 分组开启对应选项，导致网关无法识别该 AppCode。

行动：已在工单中附上完整报错信息、AppCode 和请求 ID，等待商家回复。

备用方案：如果商家迟迟未回复，将直接使用阿里云 CloudAuth 接口（已成功验证），或手动构造一个模拟的身份验证接口供演示使用。

教训：

· 很多 API 的“简易认证”功能并不是自动开启的，需要商家在后台手动配置
· 提交工单时，带上完整的报错信息比空泛的描述“调用失败”有效得多
· 永远准备备用方案，不依赖单一的外部服务

七、Windows 开发环境配置（持续补充）

安装 Git：用 winget install --id Git.Git -e --source winget 在线安装或手动下载 Git for Windows 安装包（国内镜像源更快）。

安装 VS Code：用 winget install Microsoft.VisualStudioCode 在线安装，或手动下载 .exe 安装包。同步设置：通过账号登录或 Settings Sync 扩展自动恢复插件和配置。

安装 Go：去 https://go.dev/dl/ 下载最新的 Windows 安装包（.msi 文件），双击安装。安装完成后在 VS Code 里装 Go 扩展并启用。

安装 C 编译器：用 MSYS2 安装 MinGW-w64（pacman -S mingw-w64-ucrt-x86_64-gcc），或直接用 winget install -e --id Microsoft.VisualStudio.BuildTools 装 MSVC 工具链。

安装 Docker Desktop：去 https://www.docker.com/products/docker-desktop/ 下载 Windows 版安装包，安装后确保 WSL2 后端正常运行（wsl --install 初始化）。

八、核心教训总结

1. 永远不要用 -f 参数强制重启，这是最大的坑——系统崩溃、数据丢失、文件系统全部瘫痪。
2. 分区调整后立即做正常重启，不要拖延，不要叠加其他操作。
3. 做任何危险操作前，提前备份。U 盘备份花 10 分钟，重装系统花 2 天。
4. 多留一个备用启动盘。Live USB 启动盘是救急的神器。
5. 第三方 API 对接时，预留备用方案。不要被一个厂商的配置问题卡住整个项目进度。
