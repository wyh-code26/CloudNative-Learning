今日精读：Deployment 的 restartPolicy — 和今天配的 --restart=unless-stopped 完全同构

英语原文 (Kubernetes 官方文档)

Restart Policy
A PodSpec has a restartPolicy field with possible values Always, OnFailure, and Never. The default value is Always. restartPolicy applies to all containers in the Pod. restartPolicy only refers to restarts of the containers by the kubelet on the same node.

Deployment
A Deployment provides declarative updates for Pods and ReplicaSets. You describe a desired state in a Deployment, and the Deployment Controller changes the actual state to the desired state at a controlled rate.

中文翻译

重启策略
PodSpec 有一个 restartPolicy 字段，可选值为 Always、OnFailure 和 Never。默认值是 Always。restartPolicy 适用于 Pod 中的所有容器。restartPolicy 仅指同一节点上 kubelet 对容器的重启。

Deployment（部署）
Deployment 为 Pod 和 ReplicaSet 提供声明式更新。你在 Deployment 中描述一个期望状态，Deployment 控制器会以受控速率将实际状态改变为期望状态。

映射到今天做的事情

今天执行了 docker update --restart=unless-stopped midun-zkp。在 K8s 里，这个配置是写在一个叫 Deployment 的 YAML 文件里的，不需要手动执行任何 docker update 命令。

今天做的 K8s 里的等价行为
docker update --restart=unless-stopped midun-zkp 在 Deployment YAML 里写 restartPolicy: Always（默认值，不需要显式写）
容器崩溃后 Docker 自动重启 kubelet 检测到 Pod 崩溃，自动在同节点重启容器
服务器重启后容器自动启动 Deployment Controller 检测到 Pod 数量不足，自动补到期望副本数

本质：今天手动配的 --restart=unless-stopped，是 Docker 层面的“进程守护”。K8s 把这个能力上移了一层——restartPolicy 是 Pod 级别的属性，由 kubelet 执行；而 Deployment Controller 更进一步，它不关心单个容器是否崩溃，只关心“当前有几个 Pod 在跑”是否等于“我要几个 Pod”。如果少了一个，它就补一个新的。这和你在 main.go 里写的逻辑一样——只声明期望状态，让 Controller 自动收敛。
