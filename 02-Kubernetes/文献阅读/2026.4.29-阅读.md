今日精读：Deployment 的滚动更新（RollingUpdate）

今天反复执行了 docker stop midun-zkp && docker rm midun-zkp && docker run -d --name midun-zkp ... 来更新服务版本。在 K8s 里，这个操作被 Deployment 完全自动化了，不会造成任何服务中断。

英语原文（Kubernetes 官方文档）

A Deployment provides declarative updates for Pods and ReplicaSets. You describe a desired state in a Deployment, and the Deployment Controller changes the actual state to the desired state at a controlled rate.

The Deployment controller replaces the old Pods by new ones in a controlled way. During the update, it ensures that a certain number of Pods are always running. This process is known as rolling update.

中文翻译

Deployment 为 Pod 和 ReplicaSet 提供声明式更新。你在 Deployment 中描述一个期望状态，Deployment 控制器会以受控的速率将实际状态改变为期望状态。

Deployment 控制器以可控的方式用新 Pod 替换旧 Pod。在更新过程中，它确保一定数量的 Pod 始终处于运行状态。这个过程被称为滚动更新。

今天你的操作 vs K8s 自动操作

步骤 今天做的 K8s 里的等价行为
更新镜像 docker build -t midun-server:v1.13 . 修改 Deployment YAML 的 image 字段，然后 kubectl apply
停旧容器 docker stop midun-zkp && docker rm midun-zkp Deployment Controller 检测到当前 Pod 镜像 ≠ 期望镜像，开始逐步替换
启新容器 docker run -d --name midun-zkp ... Controller 创建新的 ReplicaSet，启动新版 Pod，等新版 Pod 健康检查通过后再停掉旧 Pod
验证 curl http://127.0.0.1:8090/health readinessProbe 自动检测新 Pod 是否准备好接收流量

核心区别：今天手动做的时候，服务有短暂中断（旧容器被删、新容器还没启动的那 1-2 秒）。Deployment 的滚动更新通过控制 maxSurge（最多多出几个 Pod）和 maxUnavailable（最多允许几个 Pod 不可用）两个参数，保证更新过程中始终有 Pod 在提供服务。

与之前学的关联：之前你给 midun-zkp 加了 --restart=unless-stopped，这是容器级别的自动重启。Deployment 的滚动更新是比这更高一个层级的能力——它不仅确保单个容器崩溃后能重启，还确保整个应用在版本升级过程中不中断服务。两者结合，就是云原生的完整弹性保障。
