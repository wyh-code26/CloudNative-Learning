今日精读：PodDisruptionBudget — 主动维护时的“安全保障”

原文 (Kubernetes 官方文档)

A PodDisruptionBudget is a policy that limits the number of Pods of a replicated application that are down simultaneously from voluntary disruptions. For example, a quorum-based application would like to ensure that the number of replicas running is never brought below the number needed for a quorum.

中文翻译

Pod 中断预算 (PDB) 是一种策略，限制了在自愿性中断（如节点维护、kubectl drain）中同时不可用的 Pod 数量。例如，一个基于仲裁的应用程序希望确保运行的副本数永远不会低于法定人数所需的数量。

底层原理与《密盾》项目映射

你今天在系统崩溃后重装 Ubuntu 之前，先做了备份——这就是人工版的 PDB。PDB 告诉 K8s：“不管你怎么驱逐 Pod，我的服务最少要保持 N 个副本在线。”你在重装前确保数据已经安全转移到 U 盘，也是在做同样的事：在“中断”发生前，先保证“数据安全”这条底线不被突破。修复 GRUB 引导后执行 update-grub 自动检测 Windows 分区的过程，就类似于 PDB 确保 Pod 数量不低于阈值——最多只允许 N 个副本同时不可用，类似于引导程序“至少有一个操作系统可以启动”。

面试锚点

Q: PDB 和 ReplicaSet 有什么区别？
A: ReplicaSet 保证 Pod 总数等于期望值。PDB 则是在主动驱逐 Pod 时限制同时不可用的数量。两者互补：ReplicaSet 管理常态，PDB 管理变更窗口。
