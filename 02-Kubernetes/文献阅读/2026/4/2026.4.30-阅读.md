今日精读：readinessProbe — 健康检查的“自动化版本”

昨天手动执行了 curl http://127.0.0.1:8090/health 来验证新版本容器是否正常。在 K8s 里，这个动作被 readinessProbe 自动化了。

英语原文（Kubernetes 官方文档）

The kubelet uses readiness probes to know when a container is ready to start accepting traffic. A Pod is considered ready when all of its containers are ready. One use of this signal is to control which Pods are used as backends for Services. When a Pod is not ready, it is removed from Service load balancers.

中文翻译

kubelet 使用就绪探针来判断容器何时准备好开始接收流量。当 Pod 中的所有容器都就绪时，该 Pod 被视为就绪。此信号的一个用途是控制哪些 Pod 被用作 Service 的后端。当 Pod 未就绪时，它将从 Service 的负载均衡器中移除。

和昨天做的事情直接对应：

你昨天做的 K8s 里的等价行为
docker build -t midun-server:v1.13 修改 Deployment 的镜像版本
docker stop midun-zkp && docker rm midun-zkp Deployment Controller 开始滚动更新
docker run -d ... Controller 创建新版 Pod
sleep 2 && curl http://127.0.0.1:8090/health readinessProbe 自动检测 /health 接口
看到 {"status":"ok"}，确认新版正常 kubelet 标记 Pod 为 Ready，加入 Service 后端池

底层本质：readinessProbe 的本质是一个自动化判定机制——用你定义的规则（HTTP 接口返回 200、TCP 端口可通、执行命令返回 0）代替人工 curl 验证。它让 K8s 知道“这个 Pod 现在能不能接流量”，如果不能，就暂时把它从负载均衡里摘掉，等它恢复后再加回去。你昨天手动做的“sleep 2 + curl 验证”，就是 readinessProbe 的人工版本。
