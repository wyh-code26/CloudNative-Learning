今日精读：Deployment — Pod 的滚动更新管理器
K8s 官方文档对 Deployment 的定义非常精练，以下是最核心的一段。

英语原文 (Kubernetes 官方文档)

A Deployment provides declarative updates for Pods and ReplicaSets.

You describe a desired state in a Deployment, and the Deployment Controller changes the actual state to the desired state at a controlled rate. You can define Deployments to create new ReplicaSets, or to remove existing Deployments and adopt all their resources with new Deployments.

The Deployment controller replaces the old Pods by new ones in a controlled way. During the update, it ensures that a certain number of Pods are always running. This process is known as rolling update.

中文翻译

Deployment 为 Pod 和 ReplicaSet 提供声明式更新。

你在 Deployment 中描述一个期望状态，Deployment 控制器会以受控的速率将实际状态改变为期望状态。你可以定义 Deployment 来创建新的 ReplicaSet，或删除已有的 Deployment 并接管其所有资源。

Deployment 控制器以可控的方式用新 Pod 替换旧 Pod。在更新过程中，它确保一定数量的 Pod 始终处于运行状态。这个过程被称为滚动更新（rolling update）。


  Declarative updates（声明式更新）是 K8s 的核心设计哲学：你只声明“我要 3 个 nginx:1.26 的 Pod”，不关心“怎么把旧的换成新的”。
  Controlled rate（受控速率）指的是 maxSurge 和 maxUnavailable 两个参数，控制滚动更新时最多多出几个 Pod、最多允许几个 Pod 不可用。

  昨天给 mini-apiserver 打 tag v2.0.0，执行了停旧进程→替换二进制→启动新进程。在 K8s 里，Deployment 就是做这件事的自动化版本。

  Deployment 的本质：一个控制循环，不断检查“当前有多少个 Pod 在跑”是否等于“你声明要多少个 Pod”。如果少了就创建，多了就删除，版本不对就逐步替换。

滚动更新流程（RollingUpdate）：

  1. 你修改 Deployment 的镜像版本（比如 nginx:1.25 → nginx:1.26）
  2. Deployment 创建一个新的 ReplicaSet，逐步启动新版 Pod
  3. 每启动一个新版 Pod 并确认健康检查通过，就停掉一个旧版 Pod
  4. 直到所有 Pod 都是新版，旧 ReplicaSet 保留（方便回滚）

与你昨晚操作的映射：

```
你的操作：备份旧版 → 停旧进程 → 启动新进程 → 验证
Deployment：创建新 ReplicaSet → 逐步替换 → 旧 ReplicaSet 保留 → 健康检查确认
```

设计哲学：你备份 /root/mini-apiserver.bak2 是为了回滚；Deployment 保留旧 ReplicaSet 也是为了回滚（kubectl rollout undo）。同一目标，不同实现层级。
