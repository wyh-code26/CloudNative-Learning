今日精读：Node Affinity — 将 Pod 精准调度到指定节点

原文 (Kubernetes 官方文档)

Node affinity is a property of Pods that attracts them to a set of nodes (either as a preference or a hard requirement). Taints are the opposite — they allow a node to repel a set of Pods. There are two types of node affinity: requiredDuringSchedulingIgnoredDuringExecution and preferredDuringSchedulingIgnoredDuringExecution.

中文翻译

节点亲和性是 Pod 的一个属性，它将 Pod 吸引到一组节点上（作为偏好或硬性要求）。污点则相反——它们允许节点排斥一组 Pod。节点亲和性有两种类型：requiredDuringSchedulingIgnoredDuringExecution 和 preferredDuringSchedulingIgnoredDuringExecution。

核心词汇提取

术语 解释
Node Affinity (节点亲和性) Pod 指定自己“喜欢”去哪些节点
requiredDuringScheduling 硬性要求：Pod 只能调度到满足条件的节点，否则不调度
preferredDuringScheduling 软性偏好：Pod 更想去满足条件的节点，但不满足也能调度

底层原理与《密盾》项目映射

你在系统恢复后重装 Ubuntu 时，需要在特定分区上安装系统——这就是一种硬性要求。K8s 的 Node Affinity 也是做类似的事情：你通过标签告诉 K8s“这个 Pod 必须运行在 SSD 节点上”或者“这个 Pod 更想去 GPU 节点上”，Scheduler 在调度时就会优先满足这些约束。这和你在磁盘分区时指定的“未分配空间只能被 Windows 安装”是同一种约束思维。

面试锚点

Q: Node Affinity 和 NodeSelector 有什么区别？
A: NodeSelector 是最简单的节点选择方式，只能匹配精确的键值对，逻辑是“等于”。Node Affinity 则支持更丰富的匹配表达式，包括 In、NotIn、Exists、DoesNotExist 等，还能区分硬性要求和软性偏好。在实际生产环境中，Node Affinity 已经完全取代了 NodeSelector 的复杂场景应用。
