今日精读：Service 的三种类型 — ClusterIP、NodePort、LoadBalancer

官方定义原文

Service
A Service is a method for exposing a network application that is running as one or more Pods in your cluster.

The default service type is ClusterIP, which exposes the service on the internal IP of the cluster, so that the service is reachable only from within the cluster.

NodePort: With this method, Kubernetes exposes a service on a port on the node IP address. The port is exposed on all cluster nodes, and each node redirects traffic to the endpoints (pods) of the service. A NodePort service and a ClusterIP service are automatically created when a LoadBalancer service is provisioned.

LoadBalancer: On cloud providers which support external load balancers, setting the type field to LoadBalancer provisions a load balancer for your Service. The external load balancer can handle redirecting traffic to pods directly in the cluster.

Source: Kubernetes Official Documentation & Oracle Cloud Native Environment Documentation

中文翻译

Service（服务）
Service 是一种将运行在集群中一个或多个 Pod 上的网络应用暴露出来的方法。

默认的 Service 类型是 ClusterIP，它在集群的内部 IP 上公开服务，因此该服务只能在集群内部访问。

NodePort（节点端口）：通过这种方法，Kubernetes 在每个节点的 IP 地址上暴露一个端口。该端口在所有集群节点上都会被公开，每个节点都会将流量重定向到服务的端点（Pod）。当你配置 LoadBalancer 类型的 Service 时，会自动创建一个 NodePort 服务和一个 ClusterIP 服务。

LoadBalancer（负载均衡器）：在支持外部负载均衡器的云平台上，将 type 字段设置为 LoadBalancer 会为你的 Service 配置一个负载均衡器。外部负载均衡器可以将流量直接重定向到集群中的 Pod。

来源：Kubernetes 官方文档 & Oracle Cloud Native Environment 文档

精简笔记

Service 是 K8s 中将 Pod 暴露为网络服务的抽象层，它有三种核心类型：

类型 访问范围 典型场景 对应你的项目
ClusterIP 仅集群内部 微服务间通信、后端数据库连接 http://127.0.0.1:8090（只有服务器自己能访问）
NodePort 集群外部（通过节点IP+端口） 开发测试、简单外部访问 mini-apiserver 的 8081 端口
LoadBalancer 公网（通过云厂商负载均衡器） 生产环境对外服务 https://zkp.wuyuhangcn.com（Nginx 充当了负载均衡器的角色）

关键点：

· ClusterIP 是默认类型，只提供集群内部访问能力
· NodePort 建立在 ClusterIP 之上，在每个节点上打开一个固定端口（范围 30000-32767）
· LoadBalancer 建立在 NodePort 之上，通过云厂商的负载均衡器向公网暴露服务
· 当你创建 LoadBalancer 类型的 Service 时，会自动创建 NodePort 和 ClusterIP 服务
· 你现在用 Nginx 手动实现的一切，Service 都在集群里自动完成——工具会变，但排错思维不会
