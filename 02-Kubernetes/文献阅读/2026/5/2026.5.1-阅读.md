今日精读：Service — 解耦协作的“合约”

今天画的业务架构图里写了：“用户向验证方出示凭证，不直接找签发方”。这个解耦思想，恰好是 K8s Service 的精髓。

英语原文 (Kubernetes 官方文档)

An abstract way to expose an application running on a set of Pods as a network service. With Kubernetes you don't need to modify your application to use an unfamiliar service discovery mechanism. Kubernetes gives Pods their own IP addresses and a single DNS name for a set of Pods, and can load-balance across them.

中文翻译

一种将运行在一组 Pod 上的应用作为网络服务公开的抽象方法。使用 Kubernetes，你无需修改应用程序即可使用陌生的服务发现机制。Kubernetes 为 Pod 提供自己的 IP 地址、为一组 Pod 提供单一 DNS 名称，并可在它们之间进行负载均衡。

底层本质：Service 就是一份“网络合约”。它把“谁在干活”（动不动就重启的 Pod）和“活怎么干”（不变的IP和域名）彻底解耦。就像你今天画的图：用户需要的是“验证凭证”这个结果，他不用、也不该去找签发方。Service 就是 K8s 世界里实现这种解耦的通用机制。
