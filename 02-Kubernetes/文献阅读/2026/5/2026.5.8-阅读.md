今日精读：Deployment 的滚动更新 — 你今晚“停旧启新”操作的自动化版本

原文 (Kubernetes 官方文档)

A Deployment provides declarative updates for Pods and ReplicaSets. You describe a desired state in a Deployment, and the Deployment Controller changes the actual state to the desired state at a controlled rate.

The Deployment controller replaces the old Pods by new ones in a controlled way. During the update, it ensures that a certain number of Pods are always running. This process is known as rolling update.

中文翻译

Deployment 为 Pod 和 ReplicaSet 提供声明式更新。你在 Deployment 中描述一个期望状态，Deployment 控制器会以受控的速率将实际状态改变为期望状态。

Deployment 控制器以可控的方式用新 Pod 替换旧 Pod。在更新过程中，它确保一定数量的 Pod 始终处于运行状态。这个过程被称为滚动更新。

核心词汇提取

术语 解释
Declarative updates (声明式更新) 只描述你想要的最终状态（如：跑 v1.15 版本的镜像），不关心中间步骤。
Deployment Controller (控制器) 一个后台进程，持续监控实际状态与期望状态的差异，自动执行变更。
Rolling update (滚动更新) 逐个替换 Pod，旧 Pod 被逐步缩容到零，新 Pod 逐步扩展到期望数量。
ReplicaSet (副本集) Deployment 为每个版本创建一个 ReplicaSet，用于管理该版本的 Pod 数量。

底层原理与《密盾》项目映射

今晚你做的事情，其实就是一个人工版的滚动更新：

1. 构建新镜像：docker build -t midun-server:v1.15 .
2. 停掉旧容器：docker stop midun-zkp && docker rm midun-zkp
3. 启动新容器：docker run -d --name midun-zkp ...
4. 验证：curl http://127.0.0.1:8090/health

在 K8s 里，这个过程被 Deployment Controller 完全自动化了。你只需修改 Deployment YAML 中的 image 字段（比如从 v1.14 改成 v1.15），然后 kubectl apply。Controller 会自动创建一个新的 ReplicaSet，启动新版 Pod，等新版 Pod 健康检查通过后，再把旧版 Pod 逐步停掉。

今晚的体验恰好揭示了滚动更新的核心价值：你手动 docker stop 的瞬间，服务是中断的（虽然只有几秒）。而 Deployment 通过控制 maxSurge（最多超量 Pod 数）和 maxUnavailable（最多不可用 Pod 数）两个参数，保证了更新过程中始终有 Pod 在运行。这就是从“手动运维”到“自动化高可用”的关键一步。

面试锚点

Q: 什么是滚动更新？和你手动停旧启新有什么区别？
A: 滚动更新是 Deployment 自动执行的 Pod 替换策略。它会逐个启动新版 Pod，等新版通过健康检查后，再停掉旧版 Pod。和我手动 docker stop && docker run 的本质区别在于：滚动更新通过控制最大超量和最大不可用 Pod 数，保证了更新过程中服务不中断。手动操作则一定会造成短暂的服务不可用。
