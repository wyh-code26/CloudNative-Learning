今日精读：ConfigMap 与 Secret — 配置与敏感信息管理

原文 (Kubernetes 官方文档)

A ConfigMap is an API object used to store non-confidential data in key-value pairs. Pods can consume ConfigMaps as environment variables, command-line arguments, or as configuration files in a volume.
A Secret is an object that contains a small amount of sensitive data such as a password, a token, or a key.

中文翻译

ConfigMap 是用于以键值对形式存储非敏感数据的 API 对象。Pod 可将 ConfigMap 用作环境变量、命令行参数或卷中的配置文件。
Secret 是包含少量敏感数据（如密码、Token、密钥）的对象。

底层原理与《密盾》项目映射

昨天你在 Go 代码中硬编码了快瞳 OCR 的 Token（token := "a62c..."），这正是 Secret 要解决的典型反模式。在 K8s 中，Token 应存入 Secret，然后在 Deployment 中将其注入为容器的环境变量。代码中只用 os.Getenv("KUAITONG_TOKEN") 读取，无需暴露明文。

ConfigMap 则适合存非敏感配置——比如 OCR 接口地址、年龄阈值（18）、凭证有效期（3600秒）。ConfigMap 明文存储在 API Server 中，Secret 支持 Base64 编码和 etcd 加密，可通过 RBAC 控制访问权限。两者的本质区别在于安全设计，而非功能差异。

面试锚点

Q: ConfigMap 和 Secret 有什么区别？
A: ConfigMap 存非敏感配置，明文可读；Secret 存敏感信息（密码、Token），Base64 编码且可加密存储，支持 RBAC 精细权限控制。
